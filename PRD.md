# PRD — City Guide

**Статус:** початкова концепція, не фінальні вимоги.  
**Дата:** 20 листопада 2026 року.

## 1. Назва та опис

**City Guide** — вебзастосунок, що знаходить місто за введеною назвою й показує список цікавих місць із зовнішнього джерела даних. Перший реліз не потребує акаунтів та власного каталогу локацій.

## 2. Проблема або потреба

Людина в новому або знайомому місті хоче швидко зрозуміти, які місця можна відвідати. Їй потрібен простий перегляд варіантів без складного планування поїздки чи зайвих дій.

Це **припущення про потребу**, яке ще слід перевірити з потенційними користувачами.

## 3. Цільова аудиторія

Основна: туристи та люди, які відвідують незнайоме місто. Додаткова: нові мешканці й місцеві жителі, які шукають ідеї для дозвілля.

## 4. Цінність продукту

**Ввести місто → швидко отримати зрозумілий список цікавих місць → вибрати локацію.** Важливі простота, зрозумілі результати та мінімум кроків.

## 5. Головний сценарій

1. Користувач відкриває головний екран і вводить назву міста.
2. Застосунок шукає місто та, якщо є кілька збігів, пропонує обрати потрібне із зазначенням країни/регіону, якщо дані доступні.
3. Після вибору міста застосунок запитує цікаві місця через зовнішній API.
4. Користувач бачить список місць з назвою, доступною категорією та короткою інформацією (якщо API її надає).
5. Користувач обирає місце зі списку. У MVP вибір означає перегляд відповідного результату; окрема детальна сторінка не потрібна.

Якщо місто чи місця не знайдені або сервіс недоступний, застосунок показує зрозуміле повідомлення та можливість повторити пошук.

## 6. Попередня структура

- **Головний екран:** назва продукту, поле введення міста, кнопка пошуку.
- **Вибір міста:** варіанти міст, коли є кілька збігів (може бути частиною головного екрана).
- **Результати:** назва обраного міста, список знайдених місць, повідомлення про відсутність даних або помилку.

## 7. MVP — перший реліз

- Введення й надсилання назви міста.
- Пошук міста через зовнішнє джерело; вибір серед неоднозначних збігів.
- Отримання списку місць через зовнішній API для обраного міста.
- Відображення списку простих карток/рядків: назва, категорія й доступна коротка інформація. Не вимагати від API полів, яких він не гарантує.
- Стани: завантаження, місто не знайдено, місць немає, помилка запиту; повторний пошук.

**Не є обов'язковими для MVP:** акаунти, власна база даних, адмінпанель, карта, фотографії, рейтинги, бронювання.

## 8. Пізніше, не в MVP

1. Фільтри за категоріями, районами та інтересами.
2. Детальна сторінка місця з фотографіями (за наявності дозволених даних).
3. Інтерактивна карта.
4. Обране та персональні добірки.
5. Рейтинги й відгуки (лише за наявності законного та придатного джерела даних).

## 9. Зовнішні дані / API

- **Варіант для первинної перевірки:** [OpenTripMap API](https://dev.opentripmap.org/product) — заявлені пошук координат населеного пункту та отримання списку місць. Його [безплатний тариф](https://dev.opentripmap.org/price) на дату перевірки позначено як **non-commercial**: це не дозвіл на комерційний запуск.
- **Альтернатива для місць:** [Geoapify Places API](https://apidocs.geoapify.com/docs/places/) — пошук POI за категорією та територією.
- **Якщо потрібен окремий пошук міст:** [GeoNames Search](https://www.geonames.org/export/geonames-search.html) — пошук географічних назв.

Остаточний вибір залежить від покриття цільових міст, наявності кафе/парків/музеїв, підтримки української мови, ліцензій, обмежень запитів і вартості. Не передбачається, що один API гарантовано покриває всі категорії.

## 10. Припущення та відкриті питання

- **Географія:** припускаємо пошук міст у різних країнах; перед розробкою визначити країни або міста для першого тестування.
- **Наповнення:** перевірити на 3–5 містах, чи API повертає достатньо різноманітні й коректні локації, зокрема кафе.
- **Межі міста:** вирішити, чи показувати лише місця в адміністративних межах, чи також поблизу.
- **Мова:** узгодити мову інтерфейсу та поведінку, якщо назви/описи місць відсутні українською.
- **Вибір місця:** перевірити, чи достатньо користувачу побачити місце у списку, чи для реальної користі потрібне посилання на джерело або карту.
- **Ліцензія й ліміти:** перевірити умови використання, атрибуцію, ключі API, поточну ціну та обмеження вибраного провайдера.

**Поза межами цього PRD:** архітектура, схема бази даних, API-контракти, розподіл ролей і технічні задачі — їх визначатимемо окремо під час реалізації.
