# Tasks

## 1. Підготовка та конфігурація

- [ ] 1.1 Підготувати структуру для функції пошуку міста (UI-шаблон, серверний endpoint/обробник, ізольований адаптер Geoapify) та перевірити наявність очікуваних файлів у проєкті.
- [ ] 1.2 Додати конфігурацію Geoapify API key поза Git (локальний конфіг/середовище) та приклад `.env.example` без секретів; перевірити, що ключ читається з конфігурації і не потрапляє в репозиторій.

## 2. Інтеграція Geoapify та нормалізація даних

- [ ] 2.1 Реалізувати запит пошуку міста до Geoapify за назвою, використовуючи лише безкоштовні можливості API; перевірити на 3–5 тестових містах (напр. Київ, Львів, Warsaw, Rome, New York), що запит повертає результати без платних опцій.
- [ ] 2.2 Реалізувати фільтрацію валідних збігів лише до `city/town` та нормалізацію до контракту `place_id`, назва для відображення, країна/регіон (якщо є), `lat/lon` (якщо є); перевірити тестовими відповідями/fixture, що нерелевантні типи відкидаються і поля нормалізуються коректно.
- [ ] 2.3 Реалізувати обробку помилок Geoapify (мережа, недоступність, неуспішна відповідь) і порожніх результатів після фільтрації; перевірити, що UI отримує розрізнювані стани «не знайдено» та «помилка запиту».

## 3. Інтерфейс пошуку та вибору міста

- [ ] 3.1 Реалізувати головний екран пошуку: назва продукту, поле введення міста, кнопка пошуку, стан завантаження; перевірити вручну, що submit блокує повторне надсилання під час запиту і показує loading.
- [ ] 3.2 Реалізувати відображення списку збігів з назвою та країною/регіоном (якщо є), включно з випадком одного збігу; перевірити вручну, що один результат не обирається автоматично і потребує кліку.
- [ ] 3.3 Реалізувати явний вибір міста кліком і збереження обраного міста в стані поточного екрана за контрактом `place_id`, назва, країна/регіон, `lat/lon` (за наявності); перевірити вручну або скриптом, що стан містить усі доступні поля після вибору.
- [ ] 3.4 Реалізувати стани «місто не знайдено» та «помилка запиту» з можливістю повторити пошук; перевірити вручну обидва сценарії та відновлення після повторної спроби.

## 4. Перевірка та документація

- [ ] 4.1 Задокументувати налаштування Geoapify, обмеження поточного етапу (лише безкоштовні можливості, без nearby, без БД/адмінки, без зображень; карти можливо пізніше іншим API) та кроки ручної перевірки; перевірити, що інструкція дозволяє локально запустити й перевірити функцію.
- [ ] 4.2 Виконати фінальну ручну перевірку сценаріїв зі `specs/city-search/spec.md` на тестових містах і зафіксувати результат перевірки; підтвердити, що поза scope не додано карти, nearby, БД, адмінку чи зображення.
